# AgentMicro 产品定义

## 一句话定位

AgentMicro 是一个 macOS 菜单栏 Agent 伴侣，让用户无需反复打开 Codex，也能看见本机任务的实时状态、当前动作和返回入口。

## 用户问题

同时运行多个 Codex 任务时，用户通常无法快速回答：

- 哪些任务仍在工作？
- 哪个任务正在思考，哪个正在执行命令？
- 哪些任务已经停下来？
- 任务属于哪个项目、哪个窗口？
- 怎样快速回到对应任务？

Codex Desktop、CLI 和 IDE 会把这些信息分散在不同进程、窗口和本地会话数据中。AgentMicro 将其压缩成一个随时可见的菜单栏入口。

## 核心价值

> 不打开 Codex，也能在几秒内知道所有本机 Codex 任务的工作状态，并一键回去。

## 目标用户

- 同时运行多个 Codex 任务的 macOS 用户。
- 在 Codex Desktop、CLI 和终端之间切换的开发者。
- 希望观察 Agent 工作但不希望引入云端服务的用户。

## 产品原则

### 状态诚实

状态必须反映能够从本地数据证明的事实。无法可靠区分时显示 `Unknown` 或使用更弱的表述，不把启发式推断包装成权威状态。

### 本地优先

任务发现和状态计算默认全部在本机完成。V1 不上传 Prompt、回复、源代码、命令输出或会话文件。

### 只读优先

观察已有 Codex Desktop 任务和控制已有任务是两件事。V1 只观察，不审批、不停止、不继续、不修改 Codex 状态。

### 菜单栏优先

最重要的信息必须在一次点击内可见。完整窗口、图表和复杂设置不能挤占 V1 的核心交互。

### 渐进增强

先可靠展示任务，再增加历史、恢复、额度、多设备和控制能力。任何新能力都要保持基础观察模式可独立工作。

## 产品边界

AgentMicro 长期可以包含五层能力：

1. **Observe**：发现任务、判断状态、展示当前动作。
2. **Return**：唤起任务所在应用或终端。
3. **Recall**：查找历史任务、查看摘要、恢复会话。
4. **Manage**：管理由 AgentMicro 自己创建的任务和审批。
5. **Extend**：用量、额度、多设备、移动端和硬件联动。

V1 只交付 Observe 和基础 Return。

## 观察任务与托管任务

产品必须长期保留两种明确模式：

- **Observed task**：由 Codex Desktop、CLI 或 IDE 创建，AgentMicro 通过本地进程和会话数据观察。状态是尽力推断，控制能力受限。
- **Managed task**：未来由 AgentMicro 通过受支持的 Codex 接口创建和管理。可以拥有更可靠的生命周期、审批和控制事件。

两者不能在 UI 或数据模型中混为一谈。外部客户端目前不能稳定接管 Codex Desktop 已经运行的活跃任务，因此控制能力只能在技术条件满足后进入后续版本。

## 隐私承诺

- 默认不联网。
- 不读取 Keychain。
- 不要求 Full Disk Access。
- 只读取已知的 Codex 进程和会话位置。
- 菜单不展示命令输出、文件内容或完整 Prompt。
- 任务标题属于潜在敏感信息，默认使用项目名；用户主动选择后才显示标题。

## V1 成功标准

- 用户能在菜单栏准确看到本机主要 Codex 任务。
- 任务状态变化在数秒内反映。
- 多任务不会重复、串线或长期保留错误状态。
- 菜单打开迅速，后台资源消耗低。
- 用户理解状态是本地观察结果，并清楚产品没有控制其任务。
